# Fit Log — 기획서

## 목적
온라인 구매한 옷의 사이즈 이력을 등록하고, 새로 사려는 옷의 실측 사이즈를 입력하면
과거 이력과 비교해 짧음/적당/넉넉 여부를 판정한다.

## MVP 범위 (1단계)
- 내 옷 이력 등록/수정/삭제 (카테고리, 브랜드, 사이즈 표기, 실측값, 착용 결과, 메모)
- 새 옷 판정: 카테고리 선택 후 실측값 입력 → 같은 카테고리 이력과 비교해 항목별/종합 핏 판정
- 외부 사이트 사이즈표 연동, 자동 크롤링은 2단계 이후 (미구현)

## 데이터 모델
`ClothingRecord`: category, brand, sizeLabel, measurements(Record<string, number>),
fitOverall(tight/perfect/loose), fitNotes, source, purchaseDate

카테고리별 실측 항목 (`CATEGORY_FIELDS`):
- 상의: 어깨너비, 가슴단면, 총장, 소매길이
- 하의: 허리단면, 엉덩이단면, 허벅지단면, 밑위, 총장
- 아우터: 어깨너비, 가슴단면, 총장, 소매길이
- 원피스: 어깨너비, 가슴단면, 허리단면, 총장

## 판정 로직 (`src/judge.ts`)
1. 입력 카테고리와 같은 카테고리의 이력 중 `fitOverall === 'perfect'`인 항목을 기준선으로 삼음
   (없으면 전체 이력으로 대체, `usedFallback` 표시)
2. 항목별로 기준선 평균값과 입력값의 차이(diff) 계산
3. 필드명에 "길이/총장/밑위" 포함 시 length 타입(짧음/적당/김), 그 외는 width 타입(타이트함/적당/넉넉함)
4. 오차 허용치(`TOLERANCE_CM`) = 1cm, 이내면 '적당'
5. 종합 판정은 타이트/넉넉 판정 개수 비교로 결정

## 저장
localStorage 단일 키(`fitlog_records`), 백엔드 없음. 기기 간 동기화 미지원.

## 향후 (2단계 후보)
- 쇼핑몰 상품 페이지 사이즈표 붙여넣기 → 파싱 자동 입력
- 브랜드 간 사이즈 편차 데이터 축적/공유
- 카테고리/실측 항목 커스터마이징 UI
- 계정/클라우드 동기화
